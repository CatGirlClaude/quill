# Minecraft 26.3 & Fabric Technical Notes (MC_NOTES.md)

This document captures version-specific mechanics, API changes, and common pitfalls in **Minecraft `26.3`** and **Fabric API `0.166.2+26.3`**, verified directly against the unobfuscated game bytecode (`javap`) and official documentation.

For why we chose Minecraft `26.3` and official Mojang names, see [docs/DECISIONS.md](DECISIONS.md).

---

## 1. Datapack Structure & Folder Naming Pitfalls

### 1.1 Singular Folder Names (Since 1.21 / Pack Format 48+)

A very common pitfall when generating datapacks is using legacy plural folder names (`functions/`, `tags/functions/`). In Minecraft `26.3`, **all registry-backed datapack directories are singular**:

| Legacy Path (<= 1.20.6, BROKEN in 26.3) | Correct Path in Minecraft 26.3 |
| :--- | :--- |
| `data/<namespace>/functions/foo.mcfunction` | `data/<namespace>/function/foo.mcfunction` |
| `data/minecraft/tags/functions/load.json` | `data/minecraft/tags/function/load.json` |
| `data/minecraft/tags/functions/tick.json` | `data/minecraft/tags/function/tick.json` |
| `data/<namespace>/loot_tables/...` | `data/<namespace>/loot_table/...` |
| `data/<namespace>/recipes/...` | `data/<namespace>/recipe/...` |
| `data/<namespace>/advancements/...` | `data/<namespace>/advancement/...` |
| `data/<namespace>/predicates/...` | `data/<namespace>/predicate/...` |
| `data/<namespace>/item_modifiers/...` | `data/<namespace>/item_modifier/...` |
| `data/<namespace>/structures/...` | `data/<namespace>/structure/...` |

### 1.2 Valid Namespace & Path Characters (`Identifier`)

Minecraft enforces strict `net.minecraft.resources.Identifier` validation:
- **Namespace** (`<namespace>`): Only lowercase `[a-z0-9_.-]`.
- **Function/Resource Path** (`<path>`): Only lowercase `[a-z0-9/._-]`.
- Uppercase letters, spaces, or special characters cause datapack loading to fail immediately with a `ResourceLocationException`. Quill's "New Namespace" and "New `.mcfunction`" dialogs must validate against these rules before creating files.

## 2. `pack.mcmeta` Format in Minecraft 26.3

### 2.1 Pack Format Constants

Verified from `net.minecraft.SharedConstants` in `26.3`:
- `SharedConstants.DATA_PACK_FORMAT_MAJOR = 121`
- `SharedConstants.DATA_PACK_FORMAT_MINOR = 0`
- `SharedConstants.RESOURCE_PACK_FORMAT_MAJOR = 97`

### 2.2 `min_format` and `max_format` (Replaces Legacy `pack_format`)

Verified from `net.minecraft.server.packs.metadata.pack.PackMetadataSection` and `PackFormat$IntermediaryFormat`:
- Since Minecraft `1.21.9` (format 65+), `min_format` and `max_format` are **required** in `pack.mcmeta`.
- Each field accepts either a single integer `121` or a `[major, minor]` pair `[121, 0]`.
- **Pitfall**: Including `"supported_formats"` when `min_format >= 65` is **explicitly rejected** by `PackFormat$IntermediaryFormat.validate(...)` and causes the datapack metadata parse to fail!
- `"pack_format"` is optional and only used if backwards compatibility with versions below format 65 is desired.

**Canonical `pack.mcmeta` generated by Quill for Minecraft `26.3`:**

```json
{
  "pack": {
    "description": "Created with Quill",
    "min_format": 121,
    "max_format": 121
  }
}
```

### 2.3 Function Tag JSON Format (`load.json` and `tick.json`)

Located at `data/minecraft/tags/function/load.json` and `data/minecraft/tags/function/tick.json`:

```json
{
  "replace": false,
  "values": [
    "my_namespace:load"
  ]
}
```

## 3. Unobfuscated Build & Loom Pitfalls (`26.1+`)

1. **Plugin ID**: Use `id 'net.fabricmc.fabric-loom'` (NOT `net.fabricmc.fabric-loom-remap`).
2. **Dependency Configurations**: Because Minecraft `26.3` is unobfuscated, `modImplementation`, `modApi`, and `modRuntimeOnly` do not exist in unobfuscated Loom. Use standard Gradle `implementation`, `api`, and `runtimeOnly`.
3. **No `mappings` Declaration**: Do not add `mappings loom.officialMojangMappings()` in `dependencies {}`—the game JAR already contains official Mojang names natively.
4. **Java 25 Requirement**: `sourceCompatibility`, `targetCompatibility`, and `options.release` must be `25`, and `quill.mixins.json` uses `"compatibilityLevel": "JAVA_25"`.

## 4. Minecraft 26.3 GUI, Input & Server Reload APIs

Always use these verified `26.3` signatures rather than older `1.20`/`1.21` APIs:

### 4.1 Opening and Checking Screens (`Gui` instead of `Minecraft`)

In `26.2+`, screen management moved from `Minecraft` to `net.minecraft.client.gui.Gui`:
- Open IDE screen: `Minecraft.getInstance().gui.setScreen(new QuillIdeScreen(...))`
- Get current screen: `Minecraft.getInstance().gui.screen()`

### 4.2 `Screen` & `GuiGraphicsExtractor` Rendering

- Override `public void extractRenderState(GuiGraphicsExtractor graphics, int mouseX, int mouseY, float delta)` on `Screen` (replaces the old `render(GuiGraphics, int, int, float)`).
- Override `public boolean isPauseScreen()` to return `false` so the world continues ticking while the IDE is open.
- Key `GuiGraphicsExtractor` drawing methods in `26.3`:
  - `graphics.fill(x1, y1, x2, y2, argbColor)`
  - `graphics.outline(x, y, width, height, argbColor)`
  - `graphics.horizontalLine(x1, x2, y, argbColor)` / `graphics.verticalLine(x, y1, y2, argbColor)`
  - `graphics.enableScissor(x1, y1, x2, y2)` / `graphics.disableScissor()`
  - `graphics.text(font, stringOrComponent, x, y, argbColor, dropShadow)` (note: `text(...)` replaces `drawString(...)`!)
  - `graphics.requestCursor(CursorType)` (allows setting I-beam text cursor or resize cursors per frame).

### 4.3 Typed Input Events on `Screen` / `GuiEventListener`

In `26.3`, input methods receive record wrappers from `net.minecraft.client.input.*`:
- `boolean mouseClicked(MouseButtonEvent event, boolean doubleClick)` — `event.x()`, `event.y()`, `event.button()`, `event.modifiers()`
- `boolean mouseReleased(MouseButtonEvent event)`
- `boolean mouseDragged(MouseButtonEvent event, double dragX, double dragY)`
- `boolean mouseScrolled(double mouseX, double mouseY, double scrollX, double scrollY)`
- `boolean keyPressed(KeyEvent event)` — `event.key()`, `event.keycode()`, `event.modifiers()`
- `boolean charTyped(CharacterEvent event)` — `event.codepoint()`, `event.codepointAsString()`

### 4.4 Fabric Key Mapping Registration

Use `net.fabricmc.fabric.api.client.keymapping.v1.KeyMappingHelper`:
```java
KeyMappingHelper.registerKeyMapping(new KeyMapping(
    "key.quill.open_ide",
    InputConstants.Type.KEYSYM,
    GLFW.GLFW_KEY_K,
    "category.quill.general"
));
```

### 4.5 Discovering and Reloading Datapacks on `MinecraftServer`

- **Datapacks root path**: `server.getWorldPath(LevelResource.DATAPACK_DIR)` resolves to `<world>/datapacks/`.
- **Reloading**:
  1. Call `PackRepository packRepo = server.getPackRepository();`
  2. Call `packRepo.reload();` so newly created datapacks are discovered.
  3. Enable any newly discovered datapack IDs (`file/<packName>`) in the selected collection passed to `server.reloadResources(selectedIds)` (returns `CompletableFuture<Void>`).
  4. Must be invoked on the main `MinecraftServer` thread (`server.execute(...)`).

## 5. Local testing

Follow this workflow to test Quill locally on your machine by cloning the repository **once** and pulling incremental updates (`git pull`) without re-downloading the project or losing local test worlds in `run/`.

### 5.1 Prerequisites

1. **Git**: Installed and available on `PATH`.
2. **JDK 25**: Required by Minecraft `26.3` (`sourceCompatibility = 25`, `options.release = 25`).
   - Recommended distributions: **Eclipse Temurin 25** (Adoptium), **Microsoft Build of OpenJDK 25**, or **Azul Zulu 25**.
   - Verify with `java -version` (must report version `25.x`).
   - If you have multiple JDKs installed, point `JAVA_HOME` to your JDK 25 installation (or pass `-Dorg.gradle.java.home=/path/to/jdk-25`).
3. **No Global Gradle Required**:
   - The repository includes the **Gradle Wrapper** (`gradlew`, `gradlew.bat`, and `gradle/wrapper/`), which automatically downloads and caches Gradle `9.8.2` inside your user home (`~/.gradle/wrapper/dists/` or `%USERPROFILE%\.gradle\wrapper\dists\`) on first run.
   - No hardcoded machine paths exist in the build scripts (`build.gradle`, `gradle.properties`, `settings.gradle`).

### 5.2 Platform Differences (Windows / macOS / Linux)

| Action | Linux / macOS (`bash` / `zsh`) | Windows (PowerShell) | Windows (CMD) |
| :--- | :--- | :--- | :--- |
| **Wrapper script** | `./gradlew <task>` | `.\gradlew.bat <task>` | `gradlew.bat <task>` |
| **Set `JAVA_HOME` (session)** | `export JAVA_HOME="/path/to/jdk-25"` | `$env:JAVA_HOME = "C:\path\to\jdk-25"` | `set "JAVA_HOME=C:\path\to\jdk-25"` |
| **Make wrapper executable** | `chmod +x ./gradlew` (if needed) | Not needed | Not needed |
| **macOS LWJGL thread flag** | Handled automatically by Fabric Loom (`-XstartOnFirstThread`) | N/A | N/A |

### 5.3 Step-by-Step: Clone Once, Update with `git pull`, and Run

#### Step 1 — Clone the repository once

```bash
git clone https://github.com/CatGirlClaude/quill.git
cd quill
```

#### Step 2 — Pull new commits before testing

Whenever new commits are pushed to the repository, stay inside your existing `quill` directory and pull the latest changes:

```bash
git pull --ff-only
```

- Because you reuse the same working directory, Gradle reuses `.gradle/` and `~/.gradle/caches/fabric-loom/26.3/`, and your singleplayer test worlds inside `run/saves/` are preserved across updates.

#### Step 3 — Run JUnit tests and build checks locally

To run the unit test suite (`test` task) or full build verification (`build` task):

```bash
# Linux / macOS
./gradlew test
./gradlew build
```

```powershell
# Windows (PowerShell)
.\gradlew.bat test
.\gradlew.bat build
```

#### Step 4 — Launch Minecraft `26.3` client locally (without `xvfb`)

On a local computer with a display/monitor (Windows, macOS, or Linux desktop with X11/Wayland), run `runClient` **directly without `xvfb-run`** (`xvfb-run` is only needed on headless Linux servers/VMs that lack a physical screen):

```bash
# Linux / macOS (Desktop with display)
./gradlew runClient
```

```powershell
# Windows (PowerShell)
.\gradlew.bat runClient
```

- Minecraft `26.3` will open in a normal desktop window using `./run/` as its game directory.
- Any worlds and datapacks you create while testing are stored in `run/saves/<world_name>/datapacks/` and ignored by Git (`.gitignore`).
